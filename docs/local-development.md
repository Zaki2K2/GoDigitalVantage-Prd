# Local development and phone QR testing

The Angular app, Express API, MongoDB database, Bootstrap styles/icons, and QR renderer run locally. A phone needs network access to the development computer; an internet connection is not required for collecting feedback. Initial dependency installation and asset downloads require internet, so install everything before disconnecting.

## Start the application

From the repository root, install dependencies once:

```powershell
npm ci
npm --prefix apps/api ci
npm --prefix apps/web ci
```

Copy `apps/api/.env.example` to `apps/api/.env` only if it does not already exist. Keep existing secrets and choose independent JWT secrets of at least 32 characters. Local defaults use API port **3100** and Angular port **4200**; MongoDB uses **27017**.

Use a local MongoDB Community Server instance with `MONGODB_URI=mongodb://127.0.0.1:27017/godigitalvantage`. On Windows, a MongoDB installation that registered the standard service can be checked with `Get-Service MongoDB` and started from an elevated terminal with `Start-Service MongoDB`. A standalone `mongod` works too: supply an existing local `--dbpath` and bind to `127.0.0.1`. No cloud database or Redis is needed for the current feedback workflow. Keep MongoDB private to the computer.

Start the API and Angular in separate terminals:

```powershell
npm run api:dev
```

```powershell
npm --prefix apps/web start -- --host 0.0.0.0
```

The app uses relative `/api/v1` URLs. Angular's existing proxy forwards `/api` to `http://127.0.0.1:3100` on the computer. This also works when the browser is on a phone: the phone contacts port 4200, and Angular makes the API connection locally. No hardcoded `localhost` API address is sent to the phone. The proxy preserves same-origin auth cookies and Angular CSRF behavior.

## Configure a QR that a phone can open

1. Connect the computer and phone to the same Wi-Fi or LAN. Guest network/client isolation must allow communication between them.
2. Run `ipconfig` on the computer and find its active Wi-Fi/Ethernet IPv4 address, such as `192.168.1.10`. Do not use a VPN, disconnected adapter, loopback, or `0.0.0.0` address.
3. Set these values in `apps/api/.env`, substituting that actual address:

   ```dotenv
   PUBLIC_APP_BASE_URL=http://192.168.1.10:4200
   CORS_ORIGIN=http://localhost:4200,http://192.168.1.10:4200
   ```

4. Restart the API after changing its environment. The legacy `PUBLIC_BASE_URL` remains supported; `PUBLIC_APP_BASE_URL` takes priority. Only HTTP(S) URLs without credentials, query strings, or fragments are accepted.
5. Open `http://192.168.1.10:4200` on the phone before scanning. If it does not load, check the Angular host binding, Windows Firewall access to port 4200 on the private network, and router client isolation. The recommended proxy setup does not require opening ports 3100 or 27017 to the phone.
6. Log in on the computer, select the business, save and publish its questionnaire, and open QR management. Check that the displayed public URL starts with the actual LAN address.
7. Preview or download the SVG/PNG and scan it. Both formats are generated by the local `qrcode` package with a four-module quiet zone; there is no external QR service.
8. The phone opens `/r/<immutable-business-slug>` without authentication. Answer the required questions, submit, and confirm the success screen. Refresh the owner's dashboard/responses view to see the stored response.

Existing `/r/:slug` links are preserved. Renaming a business or publishing a new questionnaire version does not change its slug. The network address must also remain reachable for printed QR codes to keep working: reserve the computer's IP in the router or use a stable LAN hostname resolvable by the phone. Changing the configured hostname/IP requires regenerating printed QR codes.

## Verify without internet

Disconnect the router's internet uplink while retaining the local Wi-Fi/LAN, or block outbound internet for a test browser while allowing the local app origin. Keep the computer, API, Angular, and MongoDB running. Repeat QR download, phone public-form load, submit, then owner response verification. Do not use browser offline emulation that blocks **all** network requests: submissions require the local API.

This is offline **LAN** operation, not a cached/PWA form that queues responses when the phone loses LAN access. The public form shows a retryable failure if the API is unreachable; its idempotency key prevents duplicate storage on retries. An optional Google review link requires internet when opened. Future SMS/email delivery and external integrations also require their configured services and internet. Access from a phone on cellular or a different remote network requires a separate HTTPS deployment or secure tunnel; a private LAN IP alone is not reachable remotely.

## Checks

```powershell
npm --prefix apps/api run typecheck
npm --prefix apps/api test
npm --prefix apps/api run build
npm --prefix apps/web run build
npm --prefix apps/web test -- --watch=false
npm run lint
npm run format:check
```

API integration tests use the separate `gdv_test` database and clear their test collections. They cover local QR PNG/SVG downloads and configured LAN URLs, public submissions and retries, required fields and all five question types, real dashboard aggregates, authorization/CSRF, and multi-business isolation. Do not point test configuration at production data.
