# Production performance (2026-10-20)

Investigation, measured baselines, limitations, implementation details and required Vercel/Atlas setup are in [performance-vercel.md](../../docs/performance-vercel.md).

Confirmed source issues: cached resolved Mongo connect promise masked later disconnect; sequential membership/moderation reads; empty/serialized Admin enrichment; duplicate general Admin guards on campaign endpoints; hashed static assets revalidated on repeat visits. Existing warm Mongo connection reuse, business-list request sharing, shared refresh, production lazy bundles and cron isolation were already present.

Fixes: in-flight-only Mongo promise cache; bounded pool/connect waits and idle lifetime (pool stays 5); production autoCreate/autoIndex off; parallel live authorization and Admin enrichment; skip empty lookups; Campaign router before general Admin router; opt-in secret-free api_performance logs and startup/connect Server-Timing; immutable caching restricted to hashed Angular JS/CSS. No UI or business/security rule changes. No production writes, migration, deployment, region/settings change or real email.

Live repeated public API TTFB was roughly 350?560 ms on a reused HTTPS connection, with one transient health 503 and slower fresh-connection samples. Traces show iad1 execution. Local configured Atlas connection took 2501 ms; warm pings 114?201 ms. Read-only equivalent query-probe medians: membership 337 -> 177 ms, activity with/without empty lookups 395 -> 143 ms. These are local-to-Atlas probes, not deployed before/after measurements. Atlas region/deployed URI, private endpoint ranking, true cold starts and runtime logs/memory/Fluid settings remain unverified because Vercel CLI is unauthenticated. Do not guess a region or run migrations based on the local production file.

Enable PERFORMANCE_LOGGING=true only for an approved diagnostic deployment. JSON metrics contain static route templates/method/status/region, first-invocation marker and phase durations; never raw URLs, identifiers, cookies, payloads or database values. Vercel start-type telemetry remains authoritative for cold/warm classification. Default false. Set NODE_ENV=production and colocate functions with the verified Atlas primary region. Evaluate Fluid/pool/memory from actual telemetry; no blind tuning. Inspect large Admin counts/search facets and shared cron/pool contention if slow requests remain.

Follow-up (2026-10-20): performance logs also carry authMs/dbMs/dbOps/dbState via AsyncLocalStorage (`shared/perf.ts`) and driver command monitoring (durations only, enabled only with PERFORMANCE_LOGGING=true at process start); immutable header rules use plain `:hash` patterns. Health 503 body distinguishes stale-connection (`data.status=degraded`) from connect failure (`error` envelope); see performance-vercel.md.
